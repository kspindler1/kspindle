7 · Trusted RAG testbed What the prototype is testing

Kloud is a trusted retrieval-augmented generation (RAG) system. Before scaling, it needs to prove which combination of model, library and workflow gives reliable, traceable answers. Each layer below is tested independently, so any one can change without rebuilding the rest.

1
📚 Retrieve

Pull only approved, access-controlled content from the central library. Compare library options — Databricks, Veeva, SharePoint/M365, Apollo knowledge bases — on coverage, freshness and access control.

2
🧠 Generate — test different LLMs

Run the same retrieved context through different LLMs (GPT, Claude, Llama, Mistral, Gemini and others). The Model Tradeoff Analyst agent scores capability vs. cost. Try it live in the Genie model selector.

3
🔗 Connect workflows

The connected workflow is designed to link agents — Consistency Review → Trial Builder → Rule Builder → CQL → Test Data — through MCP and Apollo/Dify workflows, so one agent's output is the next one's input.

4
✅ Verify & trust

Every answer shows its sources, is checked against a golden question set, and still needs human review before use. No patient-identifiable data enters the prototype.

Seventeen agents.
One marketplace.

A marketplace for clinical trial management: specialist agents for both the clinical team and data management, plugged into one trusted backbone so every hand-off between them is shared, traceable and faster. Every agent here is real — click a card for the full spec. Clinical Trial Consistency Review has a live interactive demo; CQL Harmonizer and CQL Builder have recorded video demos; Patient Story Teller is a real Copilot Studio bot; the rest are honestly labeled by their real status.

How the marketplace connects clinical and data management

Today the clinical team and data management hand documents back and forth by email and spreadsheet. In Kloud, both sides "shop" for the agent they need from one catalog — and every agent reads from and writes back to the same trusted library through a shared orchestration layer, so one team's output can become the next team's input.

🧭WHERE THIS IS HEADED

From individual agents.
To one connected work flow.

This is the honest state of play: real agents, solving a real problem, not yet wired together. Here's the goal, where things stand today, and what it will take to get there.

🎯THE GOAL

One work/chat flow, not fourteen separate tabs.

Put these agents into a single work or chat flow for users, and connect agents across different platforms — Apollo Studio, Microsoft Copilot Studio, wherever the next one lives — based on what each request actually needs: the knowledge required to answer it, and/or the user's preferred front door. As new use cases show up, the flow grows to include them instead of becoming another standalone tool.

Where we are today
Already solving a real problem, right now These agents are already in use across multiple Therapeutic Areas (TAs) — not a lab demo. They're removing a major, unglamorous problem: tedious manual labor in trial build, safety review, and data programming.
What keeps it trustworthy
RAG SYSTEM

Grounded, not guessing

Answers are retrieved from approved knowledge sources, not generated freeform — every output should trace back to a real document or record.

TRUSTED SYSTEM

Governed knowledge

Every agent reasons from the same approved, access-controlled content, so trust doesn't have to be re-earned agent by agent.

HUMAN IN THE LOOP

Review stays in charge

Nothing here replaces qualified review — every non-ready agent's output is still checked by a person before it's used.

🧪WHAT'S NEXT

Needs testing to reach enterprise scale.

Going from "working proof of concept, used by early adopters" to "enterprise-scalable" is the actual next milestone — more rigorous testing, the shared Databricks/MCP library from the architecture page, and the unified work/chat flow above, before this is rolled out beyond the teams already using it today.

Fine-tune the assumptions

Assumptions

  • Contracted labor: 400 hours per study at $150–$300/hour.
  • Agent coverage: 95% of the work (380 hours per study). The user handles the other 5% (20 hours per study): providing source files, importing into the EDC, and troubleshooting.
  • Agent cost: $12,000/year in total, not per study. Across 20 studies, that's $600 per study.

Pitch line

"For a single study, contracting out test data generation costs $60,000 to $120,000. Across the 20+ studies in our pilot, that would be $1.2 to $2.4 million. With the Test Data Entry Generator, BI's total cost drops to $72,000 to $132,000, saving more than $1.1 million at the lowest contracted rate, all with one agent."
